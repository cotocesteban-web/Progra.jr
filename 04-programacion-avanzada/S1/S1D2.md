# ¿Qué es Node.js ?
- Node.js es un **entorno de ejecución** de JavaScript fuera del navegador, construido sobre **V8**
-  Es **multiplataforma**, **open-source** y está orientado a un **modelo de eventos** (event loop).
-  No es un lenguaje, ni un servidor web por sí mismo.
-  **Limitación:** No es ideal para tareas muy **CPU intensivas*


#### ¿Qué es un runtime environment?
Un *runtime* es el entorno que provee todas las herramientas para ejecutar un lenguaje. En los navegadores, el entorno incluye objetos como `window` o `document`. En Node.js, el entorno incluye objetos como `global`, `process`, `fs` (file system), `http`, etc.

#### Event Loop y asincronía
Node.js funciona con un **único hilo de ejecución (single-thread)**, pero gracias a su **Event Loop** puede manejar múltiples tareas concurrentes.


## Argumentos en la línea de comandos 
### ¿Qué es `process.argv`?
`process.argv` es un **arreglo de strings** que Node.js llena automáticamente cuando ejecutas un script desde la terminal.

```js
[
  '/usr/local/bin/node',                    posición 0: ruta del ejecutable de Node
  '/Users/diegorozco//S1/S1D2.js',          posición 1: ruta absoluta al script
  'uno',                                    posición 2: primer argumento
  'dos',                                    posición 3: segundo argumento
  'tres con espacios',                      posición 4: tercer argumento
  '42'                                      posición 5: cuarto argumento
]
```

> Nota: **todos** los elementos de `process.argv` son **strings**.

### Conversión de datos
```js
const num1 = Number(process.argv[2]);
const num2 = Number(process.argv[3]);
const altura = parseFloat(process.argv[4]);
const edad = parseInt(process.argv[5], 10);

if (isNaN(num1) || isNaN(num2)) {
    console.error("Por favor, proporciona dos números como argumentos.");
    console.log("Uso: node suma.js <num1> <num2>");
    process.exit(1);
}

const resultado = num1 + num2;
console.log(`La suma de ${num1} y ${num2} es: ${resultado}`);
```

## El objeto global en Node.js y navegadores: `window`, `global` y `globalThis`

En un navegador web, el objeto global se llama **`window`**.  


- En **navegadores**: `globalThis === window` 
- En **Node.js**: `globalThis === global` 

## Extensiones `.cjs`, `.mjs` y `.js` en Node.js — qué son, diferencias 

- **`.cjs`** → Siempre se interpreta como **CommonJS (CJS)**.
- **`.mjs`** → Siempre se interpreta como **ES Modules (ESM)**.
- **`.js`** → **Depende** de la configuración del proyecto

#### Dos sistemas de módulos en Node.js
- - **CommonJS (CJS)** (histórico): usa `require()` para importar y `module.exports`/`exports` para exportar.
- - **ES Modules (ESM)** (estándar moderno): usa `import`/`export` y permite *top-level await*.

#### ¿Qué pasa con `.js`?
La extensión **`.js`** **no fija** por sí sola el sistema; Node decide mirando el `package.json` del proyecto:

| `package.json`           | `archivo.js` | `archivo.cjs` | `archivo.mjs` |
|--------------------------|--------------|---------------|---------------|
| **sin** `"type"`         | **CJS**      | CJS           | ESM           |
| `"type": "commonjs"`     | **CJS**      | CJS           | ESM           |
| `"type": "module"`       | **ESM**      | CJS           | ESM           |


**Resumen:**  
- Si **no** declaras `"type": "module"`, entonces **`.js` ⇒ CJS**.
- Si **sí** declaras `"type": "module"`, entonces **`.js` ⇒ ESM**.


#### Diferencias de sintaxis (rápida)
**CommonJS (CJS)**  
- Importar: `const x = require("./mod.cjs")`
- Exportar: `module.exports = {...}` o `exports.algo = fn`

**ES Modules (ESM)**  
- Importar: `import x, { y } from "./mod.mjs"`
- Exportar: `export function ...`, `export const ...`, `export default ...`
